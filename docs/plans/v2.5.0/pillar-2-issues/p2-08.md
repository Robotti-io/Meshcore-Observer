# [v2.5.0][P2-08] Guide MQTT broker configuration and secret-safe connectivity checks

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Provide add/edit/remove/disable broker forms for supported authentication and named secret references.
- Preserve credential mappings during reorder/import/reconfiguration without exposing stored values unnecessarily.
- Offer explicitly requested bounded connection tests with safe diagnostics and per-broker outcomes.

## Acceptance criteria

- [ ] Forms generate authoritative valid broker configuration and preserve existing supported auth behavior.
- [ ] Secrets avoid URLs/history/browser persistence/logs/review exports; configured state can be shown safely.
- [ ] Connection tests clean up without publishing normal observer data or disrupting the live service.

## Validation expectations

Broker/schema/reorder/named-secret/diagnostic/connection cleanup fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

Broker config loader/manager, secret resolution, setup forms.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

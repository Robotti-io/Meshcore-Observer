# [v2.5.0][P2-05] Apply configuration safely with known-good recovery

**GitHub issue:** [#70](https://github.com/Robotti-io/Meshcore-Observer/issues/70)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Implement validated candidate staging, complete multi-file activation, known-good preservation, and approved restart/activation confirmation.
- Handle interrupted writes, permission errors, startup failure, and intentional offline configuration according to explicit policy.
- Keep activation/recovery transactions distinct from runtime feature logic and avoid silently destructive rollback.

## Acceptance criteria

- [ ] Invalid or partially written candidates cannot leave mixed active environment/broker/bot configuration.
- [ ] Prior working configuration and secret permissions survive all specified failure paths.
- [ ] Success reflects the approved activation criterion and rollback/recovery behavior is testable across supported platforms.

## Validation expectations

Fault injection at staging/commit/restart, migration/permission/offline and recovery fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

Configuration write/activation seam and service adapter interfaces.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

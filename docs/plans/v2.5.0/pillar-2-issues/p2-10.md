# [v2.5.0][P2-10] Reconfigure existing installations without reinstalling

**GitHub issue:** [#75](https://github.com/Robotti-io/Meshcore-Observer/issues/75)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Load current supported manual/generated configuration into guided forms without repeating onboarding.
- Preserve advanced values/comments where approved, show meaningful differences and restart requirements, and apply through the safe activation seam.
- Confirm accepted changes and provide a recovery route without requiring uninstall/reinstall.

## Acceptance criteria

- [ ] Existing valid installations remain supported and configuration errors do not overwrite working settings.
- [ ] Radio/broker/bot/general changes use the same authoritative validation and apply policy as first run.
- [ ] Manual/container users retain their supported path; the UI never silently drops settings it cannot represent.

## Validation expectations

Legacy/manual config, diff, unknown advanced fields, restart/apply failure and reopen tests; npm test and npm run lint.

## Existing seams and approval boundaries

Config loading, setup forms, safe apply/recovery.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

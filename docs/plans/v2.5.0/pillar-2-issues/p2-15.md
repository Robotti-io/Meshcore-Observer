# [v2.5.0][P2-15] Configure supported Linux service operation with least privilege

**GitHub issue:** [#80](https://github.com/Robotti-io/Meshcore-Observer/issues/80)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Implement the approved supported service integration, including systemd where selected.
- Define service user, serial access, paths/environment, permissions, restart/log/shutdown behavior, and enable/disable actions.
- Use minimal elevation for installation and keep ordinary Observer operation unprivileged.

## Acceptance criteria

- [ ] Automatic startup and restart behavior work on the documented service/platform matrix.
- [ ] Service identity and file/device access are explicit, with recoverable accepted/failing OS actions.
- [ ] Updates preserve configuration/history and failed operations do not affect unrelated services.

## Validation expectations

Unit/adapter/permission/paths/shutdown/update tests and authorized Linux service checks.

## Existing seams and approval boundaries

Approved JavaScript service adapter and static service resources.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

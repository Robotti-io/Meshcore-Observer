## Outcome and scope

- Validate the complete supported Windows/Linux/Pi setup and existing-installation workflows under agreed platform/recovery scenarios.
- Exercise interrupted multi-file apply, invalid imports, permission/service/connectivity failures, upgrades, secret protection, keyboard/responsive flows, and preserved metrics/history.
- Publish installation/reconfiguration/backup/service/troubleshooting guidance with explicit supported versions and limitations.

## Acceptance criteria

- [ ] Repository checks and practical platform/recovery evidence cover source pillar acceptance criteria.
- [ ] Operators can configure, run, reconfigure, diagnose, and recover without manually editing files or service internals.
- [ ] Upgrade/install checks preserve user configuration/secrets/history, and unmet constraints become scoped follow-ups.

## Validation expectations

npm test and npm run lint plus agreed separately authorized install/service/radio/broker checks; no live operations during issue capture.

## Existing seams and approval boundaries

Combined setup/installer/service validation and operator documentation.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

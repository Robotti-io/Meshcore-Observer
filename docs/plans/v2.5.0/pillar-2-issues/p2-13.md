# [v2.5.0][P2-13] Configure Windows automatic startup using the approved service mechanism

**GitHub issue:** [#78](https://github.com/Robotti-io/Meshcore-Observer/issues/78)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Implement the approved native automatic-startup mechanism, evaluating reuse of the existing Scheduled Task seam.
- Handle service identity/working/config/data paths, permissions, restart policy, enable/disable, and accepted OS outcomes.
- Minimize elevation and preserve existing registrations/manual startup compatibility.

## Acceptance criteria

- [ ] Users can enable automatic startup without manually creating tasks/services.
- [ ] Normal Observer execution does not require unnecessary administrator privilege.
- [ ] Install/reinstall/update/failure outcomes are accurate and recoverable; arbitrary service/system changes are excluded.

## Validation expectations

Adapter/registration/idempotency/permission and restart-path tests, plus authorized Windows checks.

## Existing seams and approval boundaries

Existing task scripts and an approved JavaScript service adapter; any language exception requires explicit approval.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

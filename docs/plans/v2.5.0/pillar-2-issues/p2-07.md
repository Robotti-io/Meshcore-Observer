# [v2.5.0][P2-07] Guide radio configuration and explicitly requested connection checks

**GitHub issue:** [#72](https://github.com/Robotti-io/Meshcore-Observer/issues/72)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Provide serial/TCP forms with supported device selection/entry and clear operator help.
- Perform bounded radio checks only on explicit operator request, with cleanup and useful port/network failure guidance.
- Use approved existing transport/runtime capability for enumeration; do not introduce a new dependency or start the full observer for a check.

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Valid supported radio configuration maps to central runtime fields; invalid values cannot activate.
- [ ] Checks are distinct from static validation and cannot race the running observer for the same device.
- [ ] Timeouts/unavailable ports/disconnects release resources and avoid unnecessary transmissions.

## Validation expectations

Transport/form/schema/active-test lifecycle fixtures and authorized platform device checks; npm test and npm run lint.

## Existing seams and approval boundaries

Existing serial/TCP transports, config schemas, setup forms.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

## Outcome and scope

- Research Windows and Linux/Raspberry Pi versions/architectures, native serial/runtime prerequisites, privilege/service mechanisms, and artifact/upgrade options.
- Recommend separated application/config/data paths, runtime bundle versus prerequisite handling, and existing Scheduled Task/systemd reuse where supported.
- Identify dependency/build/deployment or language exceptions requiring explicit approval rather than introducing packaging tooling by default.

## Dependencies

- [P2-01 — #66](https://github.com/Robotti-io/Meshcore-Observer/issues/66)

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Supported/proposed platform matrix and evidence cover Node >=22.13.0 and native serial components.
- [ ] Artifacts, permissions, code/data layout, offline/prerequisite assumptions, and upgrade preservation are explicit.
- [ ] No installer, service, system state, dependency, or CI change is made during research.

## Validation expectations

Review repo scripts and authoritative OS/runtime/package documentation; identify later platform checks.

## Existing seams and approval boundaries

Existing scripts/package metadata and supported OS facilities.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

# [v2.5.0][P2-16] Expose service status and approved start-stop-restart controls

**GitHub issue:** [#81](https://github.com/Robotti-io/Meshcore-Observer/issues/81)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Provide bounded service status and explicitly authorized lifecycle actions through the approved local admin surface.
- Coordinate setup/service process ownership so stopping or restarting Observer does not destroy the recovery/configuration path.
- Display actual accepted/running/stopped/failed state, versions and safe diagnostics with clear permissions.

## Acceptance criteria

- [ ] Requested actions are strictly validated/authorized and do not claim success before OS acceptance.
- [ ] Status/timeouts/permission failures and restart transitions are observable without secret disclosure.
- [ ] Controls target only the configured installation, use safe shutdown, and remain available as designed through service changes.

## Validation expectations

Admin request/action/status/timeout/permission/process ownership tests and authorized OS verification.

## Existing seams and approval boundaries

Local setup API, platform service adapters, activation/status components.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

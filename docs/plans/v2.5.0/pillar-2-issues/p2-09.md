## Outcome and scope

- Provide supported bot/command, dashboard, identity, retention/log-level, telemetry, discovery/publication, and advanced configuration forms.
- Render approved targeting, suppression, private transport, region scope, and fallback options with progressive disclosure.
- Reuse authoritative schemas/metadata and preserve advanced valid values rather than inventing a second configuration model.

## Acceptance criteria

- [ ] Add/edit/disable/remove and command policy fields produce centrally valid configuration.
- [ ] Optional telemetry/discovery and per-broker publication settings remain explicit and understandable.
- [ ] Forms use authoritative approved defaults, preserve valid operator overrides, and explain units/defaults consistently with example configuration and central code. Include the approved 72-hour direct-heard eligibility default from #23/#31.
- [ ] Unknown supported advanced values/manual settings are preserved or clearly surfaced, with secret-safe previews and restart guidance.

## Validation expectations

Schema/form/legacy/advanced value/preview and range of policy combination fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

Bot/general schemas, setup form/metadata helpers, settled Pillar 1/3 config.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

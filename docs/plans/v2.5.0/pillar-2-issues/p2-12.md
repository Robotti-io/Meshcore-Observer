# [v2.5.0][P2-12] Provide the approved Windows installation entry point

**GitHub issue:** [#77](https://github.com/Robotti-io/Meshcore-Observer/issues/77)

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Build the approved Windows artifact/launcher and prerequisite checks without requiring manual cloning/config file creation.
- Separate replaceable code from protected configuration/data and lead operators into local onboarding.
- Provide actionable install failures and preserve compatible existing environments during install/update.

## Acceptance criteria

- [ ] Supported Windows users can start guided installation/setup through the approved entry point.
- [ ] Runtime/native prerequisites, permissions, paths, and upgrade-preservation behavior match the platform decision.
- [ ] New dependency/build/deployment or language tooling is introduced only after explicit approval.

## Validation expectations

Packaged install/first-run/existing environment/failure fixtures and authorized supported-Windows validation.

## Existing seams and approval boundaries

Approved installer/runtime layout and repository-defined packaging scripts when added.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

# [v2.5.0][P2-03] Reuse authoritative configuration validation and provide a static doctor

**GitHub issue:** [#68](https://github.com/Robotti-io/Meshcore-Observer/issues/68)
**Labels:** `release:v2.5.0`, `pillar:simplified-setup`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 2 — #19](https://github.com/Robotti-io/Meshcore-Observer/issues/19)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Expose reusable central validation for complete proposed environment/broker/bot/general configuration.
- Provide static preflight/doctor results for required values, file/path/permission/secret references, runtime, and supported service prerequisites.
- Return actionable field/category errors without duplicating weaker schemas or activating hardware/network operations.

## Dependencies

- [P2-01 — #66](https://github.com/Robotti-io/Meshcore-Observer/issues/66)

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Setup/import/reconfiguration/doctor/startup share the authoritative strict AJV/configuration rules.
- [ ] Approved optional settings have matching example/code defaults with documented units; omitted values use central fallbacks, valid explicit overrides win, and invalid values fail. Verify example/code agreement without assigning defaults to required values or secrets. Human direction recorded on 2026-10-08 under #23.
- [ ] Invalid candidates fail before side effects and preserve current active configuration.
- [ ] Diagnostics avoid secret values and can be invoked independently after onboarding.

## Validation expectations

Valid/invalid configuration, filesystem/secret-reference/runtime/diagnostic fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

src/config, shared AJV, broker/bot loaders and setup validation interface.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

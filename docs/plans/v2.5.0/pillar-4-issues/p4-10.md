# [v2.5.0][P4-10] Refine responsive layouts and touch interaction

**GitHub issue:** [#47](https://github.com/Robotti-io/Meshcore-Observer/issues/47)
**Labels:** `release:v2.5.0`, `pillar:ui-ux`, `enhancement`

**Parent epic:** [Pillar 4 — #21](https://github.com/Robotti-io/Meshcore-Observer/issues/21)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Adapt navigation, cards, range controls, filters, tables, charts, and setup fields across approved widths.
- Keep table overflow local and long operational values available without page-level layout failure.
- Provide practical touch targets and stable populated layouts.

## Acceptance criteria

- [ ] Supported widths and realistic long/dense datasets remain usable.
- [ ] Charts retain readable dimensions and controls remain operable on touch/narrow screens.
- [ ] Responsive changes preserve focus order and operational information access.

## Validation expectations

Manual representative viewport/touch checks and meaningful layout-related logic tests.

## Existing seams and approval boundaries

Shared/client CSS and dashboard/setup layout consumers.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

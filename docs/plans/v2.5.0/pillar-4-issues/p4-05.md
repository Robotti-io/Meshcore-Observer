## Acceptance criteria

- [ ] Only approved/licensed assets are included and typography follows its approved roles.
- [ ] Offline behavior matches the decision record; missing resources have practical textual/table alternatives.
- [ ] Dependencies, CDN origins, and CSP changes are explicitly approved before implementation.
- [ ] Core insight charts and required assets work from a cold browser cache with WAN access blocked and the Observer reachable on the local network; use approved local assets rather than depending on a CDN. Missing optional artwork must not prevent insight tasks.

## Offline direction — 2026-10-08

The user directs offline-capable core operation, save first/purge later and enterprise reliability. Existing evidence: `src/web/dashboard-page.js` loads pinned Chart.js 4.4.4 from jsDelivr; `dashboard.js` guards missing Chart, allowing remaining tiles/tables/controls to operate, but charts remain unavailable without that resource. Replace this requirement with a reviewed local asset delivery plan, including version/license/integrity and container packaging; preserve strict CSP and avoid adding dependencies silently. This updates the product requirement without implementing #42 or changing its queued status. #83 must verify cold-cache WAN-loss operation; #37 owns backend capture/persistence/recovery checks.

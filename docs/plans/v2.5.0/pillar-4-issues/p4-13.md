# [v2.5.0][P4-13] Standardize product copy, metric help, and recovery guidance

**GitHub issue:** [#50](https://github.com/Robotti-io/Meshcore-Observer/issues/50)

**Parent epic:** [Pillar 4 — #21](https://github.com/Robotti-io/Meshcore-Observer/issues/21)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Review operator-facing labels, metric definitions, tooltips/help, and setup/dashboard copy.
- Explain units, unique/event counts, invocation versus delivery, freshness/unknown values, and destination ACK semantics accurately.
- Offer actionable friendly errors with separately accessible safe technical diagnostics.

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Labels/help explain meaning rather than repeating names or exposing variable names by default.
- [ ] Unknown data and ACKs are not described as healthy zero or human read receipts.
- [ ] Error/empty/recovery copy is consistent, secret-safe, and practical.

## Validation expectations

Copy review against approved data/transport semantics and affected interaction tests.

## Existing seams and approval boundaries

Page/client strings, shared help/status patterns, setup copy.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

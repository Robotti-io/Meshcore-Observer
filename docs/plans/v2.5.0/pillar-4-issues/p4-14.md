## Acceptance criteria

- [ ] Existing and new workflows pass meaningful regression and manual keyboard/responsive checks.
- [ ] Cross-view visual/interaction consistency and product copy meet the approved guidance.
- [ ] Performance comparisons, datasets, environments, limitations, and remaining findings are recorded.
- [ ] With a cold browser cache and WAN/broker access blocked, locally hosted core insight views, charts, filters, lookup and historical data remain usable. Verify the #42 local asset contract, distinguish WAN loss from loss of the Observer itself, and label stale/unavailable data truthfully. Record reproducible recovery checks without relying on previously cached CDN assets.

## Validation expectations

npm test and npm run lint plus agreed populated/browser/accessibility/performance checks; no production operations during issue capture.

## Existing seams and approval boundaries

Combined frontend validation fixtures and operational views.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

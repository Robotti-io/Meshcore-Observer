# [v2.5.0][P4-03] Centralize Robotti design tokens and product typography

**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Centralize approved color/surface/text, spacing, radius, shadows, and motion tokens in the existing CSS architecture.
- Apply readable system typography and approved OS-dark behavior without requiring display fonts in normal UI.
- Preserve contrast, operational data density, and existing dashboard functionality.

## Acceptance criteria

- [ ] Reusable tokens replace scattered values for the approved scope.
- [ ] Brand and semantic colors retain distinct roles; system/dark treatment remains readable.
- [ ] Visual regression review verifies representative views and no unapproved font/asset/CSP changes.

## Validation expectations

Inspect populated views, contrast/focus/narrow layouts; run repository checks for any changed interaction logic.

## Existing seams and approval boundaries

src/web/client/dashboard.css and static page styling.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

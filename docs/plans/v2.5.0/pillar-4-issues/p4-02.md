## Outcome and scope

- Propose information hierarchy/navigation for existing and new datasets, overview/drill-down responsibilities, and setup/dashboard consistency.
- Define Observer chart-series differentiation, units/ranges, semantic color/unknown-state behavior, and exact-value alternatives.
- Record browser/viewport/accessibility targets, component scope, offline strategy, typography/assets, and restrained motion/copy conventions; obtain approval for unresolved choices.

## Acceptance criteria

- [ ] Current, historical, unique/event, delivery, and freshness meanings align with Pillar 1 decisions.
- [ ] Charts are distinguishable beyond color; unsupported health thresholds or brand canon are not invented.
- [ ] A reviewed decision record separates required product behavior, optional enhancements, and protected-boundary proposals.

## Validation expectations

Use representative workflows/data and keyboard/narrow-screen examples; confirm design decisions before implementing styles.

## Existing seams and approval boundaries

Product UI guidance, navigation/data visualization conventions.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

# [v2.5.0][P4-11] Refine keyboard, focus, and assistive-technology semantics

**GitHub issue:** [#48](https://github.com/Robotti-io/Meshcore-Observer/issues/48)
**Labels:** `release:v2.5.0`, `pillar:ui-ux`, `enhancement`

**Parent epic:** [Pillar 4 — #21](https://github.com/Robotti-io/Meshcore-Observer/issues/21)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Audit/fix headings, field labels, table headers, control names, focus order/return, and keyboard operation.
- Provide useful bounded status announcements and chart summaries without excessive live-update noise.
- Apply approved accessibility targets consistently to setup and dashboard consumers.

## Acceptance criteria

- [ ] Primary workflows can be completed keyboard-only with visible focus.
- [ ] Forms/dialogs/tables and long identifiers expose understandable accessible names/relationships.
- [ ] Status/SSE announcements inform without repeated noise; important states do not rely on color alone.

## Validation expectations

Keyboard-only and representative assistive-technology review, plus focused semantic/interaction regressions.

## Existing seams and approval boundaries

Semantic HTML, shared helpers, dashboard/setup consumers.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

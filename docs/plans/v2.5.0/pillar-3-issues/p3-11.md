# [v2.5.0][P3-11] Track private destination ACKs and timeout outcomes

**GitHub issue:** [#62](https://github.com/Robotti-io/Meshcore-Observer/issues/62)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Correlate supported destination ACKs to the correct reply/attempt and track defined timeout/latency evidence.
- Separate send acceptance, acknowledgement, timeout, and explicit failure, including duplicates/late ACKs and reconnects.
- Keep waiting/retry work bounded and persist only the approved delivery evidence.

## Acceptance criteria

- [ ] Unrelated/stale/duplicate ACKs cannot confirm another attempt or double-count a reply.
- [ ] Missing ACK and explicit send failure remain distinct; ACK language refers to the destination node.
- [ ] Shutdown/recovery/timeout transitions remain bounded and do not starve transmission work.

## Validation expectations

ACK IDs, late/duplicate/out-of-order events, timeout/retry/restart fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

Radio ACK events, reply lifecycle persistence and reporting.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

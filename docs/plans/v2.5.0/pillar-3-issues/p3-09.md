# [v2.5.0][P3-09] Receive private contact commands through existing handlers

**GitHub issue:** [#60](https://github.com/Robotti-io/Meshcore-Observer/issues/60)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Normalize and strictly validate supported private/contact intake and enabled-command policy.
- Reuse exact/lookup/stats handler semantics while keeping transport separate from command logic.
- Preserve request identity/correlation and avoid unnecessarily logging or reporting private text.

## Dependencies

- [P3-01 — #52](https://github.com/Robotti-io/Meshcore-Observer/issues/52)
- [P3-02 — #53](https://github.com/Robotti-io/Meshcore-Observer/issues/53)
- [P3-05 — #56](https://github.com/Robotti-io/Meshcore-Observer/issues/56)

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Allowed private commands reach shared handlers with bounded validated context.
- [ ] Unsupported/malformed/duplicate messages cannot corrupt persisted state or invoke prohibited commands.
- [ ] Legacy public intake and private metadata privacy remain compatible.

## Validation expectations

Contact-message/config/deduplication/handler and malformed-state fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

Radio/private message events, handler intake, bot schemas.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

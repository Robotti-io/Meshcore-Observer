# [v2.5.0][P3-06] Suppress redundant pending replies using handler-aware response evidence

**GitHub issue:** [#57](https://github.com/Robotti-io/Meshcore-Observer/issues/57)

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Implemented; validation complete.

## Outcome and scope

- Add command-opt-in satisfactory-response recognition using request/sender/trigger/time/state evidence.
- Coordinate pending cancellation with the actual transmission-commit boundary and persist a distinct suppressed outcome.
- Keep unrelated messages, generic mentions, and commands needing multiple replies from triggering suppression.

## Implementation record

- Added opt-in `suppressIfAnswered` for exact commands. Config validation requires a sender-addressed response template (including any overflow template) and rejects lookup/stats commands until those handlers have tested matchers.
- Added an exact handler matcher that regenerates the queued response from its persisted request context and compares the full rendered message. A shared coordinator considers live pending replies across the same channel, suppresses only one unique match, and fails closed on ambiguous or oversized candidate sets. It ignores repeated packet evidence and known echoes of this Observer's own replies.
- Added the atomic pending-only suppression transition and a bounded receipt-time candidate query backed by MetricsStore schema v23's partial channel index. Suppression stores a reason but no competing message body. `queryReplyLifecycleTotals` reports suppressed and delivery-unknown independently; the existing dashboard totals/API remain unchanged.
- Added coverage for competing bot matches, false positives, overlapping requests, duplicate/late evidence, expiry, restart persistence, schema migration rollback/retry, own-reply echoes, and the dispatch-claim race.
- Validation: `npm test` passed (114 files, 1,597 tests); `npm run lint -- --ignore-pattern docs/working_docs` passed; `git diff --check` passed. Generated T1 build artifacts under `docs/working_docs` are excluded from ESLint.

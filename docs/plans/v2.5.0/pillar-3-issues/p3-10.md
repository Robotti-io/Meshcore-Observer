# [v2.5.0][P3-10] Deliver private replies through valid contacts with bounded retry and fallback

**GitHub issue:** [#61](https://github.com/Robotti-io/Meshcore-Observer/issues/61)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`, `configuration`, `security`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Deliver private requests privately using verified Companion-maintained contact routing/freshness.
- Implement approved retry and fallback policies with bounded timeouts and coordination, independent of optional topology assistance.
- Preserve operator-managed paths and distinguish direct-send acceptance from later destination ACK evidence.

## Acceptance criteria

- [ ] Inbound observed paths are not blindly reversed or installed as outbound routes.
- [ ] Missing/stale contacts, disconnects, send failure, and retries preserve capture and queue durability.
- [ ] Private failure does not create a public/unscoped flood unless explicitly configured and approved.

## Validation expectations

Contact route/age, send acceptance, retry/fallback, reconnect/reopen, and privacy fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

Contact send APIs, shared radio/reply policy, store context.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

# [v2.5.0][P3-07] Resolve per-command region scopes and explicit fallback policy

**GitHub issue:** [#58](https://github.com/Robotti-io/Meshcore-Observer/issues/58)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`, `configuration`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Validate semantic region identifiers and command/bot inheritance using the approved OKI/protocol mapping.
- Represent default, regional, and unscoped modes explicitly, preserving case/wildcard meanings as verified.
- Persist intended policy and define fail/defer/retry/explicit fallback without deriving authorization from OBS-02 declarations.

## Acceptance criteria

- [ ] Invalid/unknown scope configuration fails safely before transmission.
- [ ] Human-facing names resolve through the verified mapping; OKI names are not hard-coded into the core.
- [ ] Required scopes do not silently become broader floods, including restart/config changes.

## Validation expectations

Scope schema/mapping/default/fallback and legacy/recovery tests; npm test and npm run lint.

## Existing seams and approval boundaries

Central bot schemas, scope-resolution/delivery policy seams.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

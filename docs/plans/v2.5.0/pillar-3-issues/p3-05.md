## Outcome and scope

- Extend durable reply context to represent approved targeting/transport/scope/fallback policy and lifecycle evidence.
- Preserve versioned handler state and existing queue/migration ownership; define recovery of older pending replies and configuration changes.
- Represent suppression, transmission, ACK, timeout/failure evidence without conflating meanings or counting a delivery twice.

## Implementation record

- Added transactional MetricsStore migration v22 for delivery policy, private-recipient context, dispatch attempts, outcome reasons, and separate ACK evidence. Legacy rows retain IDs and handler state and receive an explicit channel/legacy-scope/no-fallback policy.
- Added strict AJV schemas and validated store operations for dispatch claims, terminal resolution, pending-only suppression, restart recovery, and ACK updates. Dispatch claims persist the `pending -> dispatching` commit boundary; interrupted dispatches become `delivery-unknown` on startup and are not replayed.
- Integrated the queue with durable dispatch claims and outcomes. Current channel dispatch reports `sent` or `failed`; the lifecycle model also carries approved scope/transport context for later routing work. Private message bodies are not persisted; the full recipient key is retained only for pending private replies.
- Preserved existing reply report totals and retention behavior. T6 response correlation/suppression is implemented separately; T7 scope resolution remains.
- Validation: `npm test` passed (113 files, 1,586 tests); `npm run lint -- --ignore-pattern docs/working_docs` passed; `git diff --check` passed. The ignore pattern excludes generated T1 build artifacts under `docs/working_docs` from ESLint.

# [v2.5.0][P3-08] Transmit scoped channel replies atomically and restore safe scope state

**GitHub issue:** [#59](https://github.com/Robotti-io/Meshcore-Observer/issues/59)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Hold shared radio ownership across scope application, acknowledgement where supported, send, and required restoration.
- Handle failure/disconnect/reconnect without relying on assumed firmware state or leaking another bot's scope.
- Reuse existing command/airtime coordination and preserve normal channel/advert consumers.

## Acceptance criteria

- [ ] Concurrent scoped/unscoped radio work cannot exchange scope state.
- [ ] Apply/send/restore failure handling follows verified protocol and explicit fallback rules.
- [ ] Scope state after reconnect is safe and observably handled without unrestricted retries or capture disruption.

## Validation expectations

Atomic transaction interleavings, scope failures, reconnect, and mixed radio workload fixtures; npm test and npm run lint; authorized hardware checks.

## Existing seams and approval boundaries

RadioManager/CommandQueue, AirtimeCoordinator, reply dispatcher.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

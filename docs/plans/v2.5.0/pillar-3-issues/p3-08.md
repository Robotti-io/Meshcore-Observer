# [v2.5.0][P3-08] Transmit scoped channel replies atomically and restore safe scope state

**GitHub issue:** [#59](https://github.com/Robotti-io/Meshcore-Observer/issues/59)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Persistent-scope behavior updated locally per operator direction; lint passed on 2026-11-18; automated tests and hardware validation remain pending.

## Current branch baseline

The channel-bot path persists the resolved policy with each queued reply and
holds the existing radio command owner while applying scope and sending. An
accepted region remains active for the session; the next channel reply applies
its own region or clears to device default before sending. Private replies and
scheduled flood adverts clear before their device-default transmissions.
Companion acknowledgments, captured generation checks, five-second command
timeouts, and connection retirement remain in place. A send accepted by the
Companion remains recorded as sent even if the connection changes immediately
afterward. Lint passed on 2026-11-18. Automated tests were not run, and
hardware validation remains pending.

## Outcome and scope

- Hold shared radio ownership across scope application, send, and the next send's scope transition.
- Handle failure/disconnect/reconnect without relying on assumed firmware state or leaking a channel scope into device-default sends.
- Reuse existing command/airtime coordination and preserve normal channel/advert consumers.

## Acceptance criteria

- [ ] Consecutive same-region, different-region, and device-default channel replies apply the next queued scope correctly; competing radio commands remain serialized.
- [ ] Private replies and scheduled flood adverts clear channel scope before device-default transmission.
- [ ] Apply/send/clear failure handling follows Companion acknowledgments and explicit fallback rules; uncertain acknowledgments retire the connection without retry.
- [ ] Scope state after reconnect is safe and observably handled through generation checks and connection retirement, without unrestricted retries; the existing reconnect behavior may temporarily pause radio capture.

## Validation expectations

Atomic transaction interleavings, scope failures, reconnect, and mixed radio workload fixtures; `npm test` and `npm run lint`; hardware validation under separate authorization.

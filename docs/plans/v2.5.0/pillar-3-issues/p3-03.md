# [v2.5.0][P3-03] Discover and refresh the Companion bot identity

**GitHub issue:** [#54](https://github.com/Robotti-io/Meshcore-Observer/issues/54)
**Labels:** `release:v2.5.0`, `pillar:enhanced-bots`, `enhancement`

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Feature
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Provide the current targetable Companion identity from validated device information without duplicating it in operator configuration.
- Refresh identity according to supported rename/reconnect behavior and preserve valid Unicode names within protocol limits.
- Expose a small identity seam for targeting and fail safely when identity is unavailable.

## Dependencies

- [P3-01 — #52](https://github.com/Robotti-io/Meshcore-Observer/issues/52)
- [P3-02 — #53](https://github.com/Robotti-io/Meshcore-Observer/issues/53)

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Identity-required commands cannot match every bot when identity is missing/stale.
- [ ] Renames/reconnects and valid emoji/non-ASCII names follow the approved comparison rules.
- [ ] Existing untargeted handlers and startup behavior remain compatible.

## Validation expectations

Identity unavailable/rename/reconnect/Unicode boundary fixtures; npm test and npm run lint.

## Existing seams and approval boundaries

RadioManager device info and bot matching context.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

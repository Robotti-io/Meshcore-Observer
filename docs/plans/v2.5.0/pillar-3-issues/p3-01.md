# [v2.5.0][P3-01] Assess bot targeting, private messaging, ACK, and region-scope capabilities

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)

**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Extend Pillar 1's capability evidence specifically for Companion identity/client tag syntax, private intake/sending, ACK identifiers/events, and flood-scope operations.
- Validate authoritative OKI region guidance, region-name/key derivation, firmware scope persistence/restoration, and reconnect behavior.
- Identify available dependency artifacts, unsupported cases, and testable fixtures without treating anonymous region discovery as message scoping.

## Dependencies

- [P1-01 — #22](https://github.com/Robotti-io/Meshcore-Observer/issues/22)

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] Versioned evidence separates supported, unsupported, and unknown bot-specific behavior.
- [ ] Contact routing, private ACK guarantees, client tag conventions, and atomic scope transaction requirements are explicit.
- [ ] No dependency/firmware/contact/route/credential change or live transmission occurs as part of research.

## Validation expectations

Review local library/protocol and primary community/upstream references; propose separately authorized hardware checks.

## Existing seams and approval boundaries

Existing radio/bot seams, supported firmware/library, OKI specification.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

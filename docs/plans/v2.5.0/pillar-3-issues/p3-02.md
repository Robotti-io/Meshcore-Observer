# [v2.5.0][P3-02] Define targeting, response policy, suppression, and delivery lifecycle

**GitHub issue:** [#53](https://github.com/Robotti-io/Meshcore-Observer/issues/53)

**Parent epic:** [Pillar 3 — #20](https://github.com/Robotti-io/Meshcore-Observer/issues/20)
**Type:** Decision
**Stage:** Issue scoped; implementation planning pending.

## Outcome and scope

- Define tag grammar/normalization/case/duplicate-name behavior, opt-in command policy, and backward-compatible defaults.
- Specify satisfactory-response evidence/correlation windows, the transmission-commit boundary, private/scoped fallback/retry rules, and durable reply/ACK outcomes.
- Define persistence/config-change recovery, privacy and reporting semantics; propose a small explicit policy rather than a rule engine.

Dependencies identify required evidence/interfaces for implementation. They do not require finishing an entire consuming/owning epic before independent planning. Existing shared services retain their owning issue.

## Acceptance criteria

- [ ] A reviewed decision record defines configuration inheritance, transport selection, terminal versus ACK evidence, and counting semantics.
- [ ] Only uncommitted replies are suppressible; private/scoped failures cannot silently broaden traffic.
- [ ] Names are not assumed unique, inbound paths are not assumed reversible, and ACKs are not read receipts.

## Validation expectations

Use competing-bot, duplicate-name, restart/config-change, ACK/timeout, and scope failure examples.

## Existing seams and approval boundaries

Command metadata/configuration, handler/reply queue boundaries, store ownership.

Follow AGENTS.md: JavaScript ES modules, centralized strict AJV/configuration/logging, existing seams, and always-on MetricsStore ownership. Concrete authentication, storage, public API/MQTT, dependency, logging-contract, CSP, and deployment changes require explicit approval in the implementation plan. Real hardware, service, privilege, restart, or network operations require the applicable authorization; issue capture performs none.

# [v2.5.0][P1-06] Persist passive topology and path evidence

**GitHub issue:** [#27](https://github.com/Robotti-io/Meshcore-Observer/issues/27)

**Parent epic:** [Pillar 1 — #18](https://github.com/Robotti-io/Meshcore-Observer/issues/18)
**Type:** Feature
**Stage:** Issue scoped; implementation plan pending.

## Outcome and scope

- Learn paths from ordinary observed traffic without transmitting discovery traffic or storing raw packets locally.
- Persist multiple observations/relationships with hop distance, frequency, first/last observation, and approved freshness/retention semantics.
- Resolve compact repeater identifiers conservatively against full known identities; expose reusable evidence for telemetry and future bot consumers.

## Acceptance criteria

- [ ] AC01 -> 9905 -> E85C -> Observer gives distances 3, 2, and 1; radius 2 excludes AC01.
- [ ] Multiple routes and changing recency remain distinguishable; ambiguous/unresolved identifiers cannot silently pick a target.
- [ ] Observed proximity is not claimed as proof of a valid reversible outbound route.
- [ ] Persistence/range queries survive restart with bounded growth and compatible migrations.

## Validation expectations

Path width/order/hop fixtures grounded in supported protocol, ambiguous prefixes, stale evidence, multiple paths, and migration/retention tests; npm test and npm run lint.

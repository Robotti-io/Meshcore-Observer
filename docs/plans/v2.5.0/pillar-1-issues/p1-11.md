### 2. Relevant Existing Architecture

Baseline `54a920d37871d378a65b920790f3bb1b5a27ea45` is clean and user-pushed. #30 provides immutable answers, ambiguity flags, latest snapshots, per-broker claims/tokens, retry deadlines, restart recovery and protected pending retention (migration 14). #31 atomically saves successful completions and schedules (migration 15), currently without destinations. MQTT manager/broker already isolate configured connections; central config validates broker files before startup. Shutdown has a shared ten-second deadline.

The authoritative CoreScope contract at `6cab7d698d15f739dcaa0f04df70eaa80f5d13da/docs/client-regions.md` was retrieved through GitHub on 2026-10-10. It specifies lowercase reporter topics/full target keys, ISO timestamps at millisecond precision, deliberate empty answers, optional remote clock and idempotency by reporter/target/original observation. Its truncated boolean is a hint; the firmware cannot prove completeness.

### 3. Proposed Approach

Concrete decisions PUBLICATION-PLAN-01–05, within the user's explicit implementation authorization:

1. **Contract:** fixed `meshcore/client/{lowercase reporting Companion key}/regions`; `type:REGIONS`, original millisecond ISO timestamp, lowercase full target key, unchanged regions including case/order/duplicates/`*`, `truncated:true` because completeness is unknown, optional uint32 `repeater_clock` (omit null, preserve zero). No GPS or extra fields. Strict AJV validates source and outbound object before sending.
2. **Opt-in/defaults:** each broker has optional `regionPublication.enabled:false`, normalized centrally with defaults: tick 10000ms, publish timeout 5000ms, retry base 60000ms, retry maximum 3600000ms. Strict overrides, base <= maximum, at most 64 enabled destinations, stable broker IDs. Broker enabled plus publication enabled are required. Existing broker QoS/retain settings do not alter this contract: QoS 1, retain false.
3. **Save-first/backfill:** newly successful safe answers and enabled destination records commit together using #30's existing transaction seam. Clock-anomalous/conflicting observations remain local. For later opt-in/crash before staging, bounded indexed keyset pages backfill the latest safe retained answer per reporter/target; this is not a bulk export of old history. Previously pending deliveries remain protected and eligible. No new table/migration, purge, retention change or RF retry is needed.
4. **Delivery/retry:** one in-flight attempt per opted-in broker, independent jobs and durable capped exponential retry with original payload/time. Only the current ready Companion's matching reporter identity may send; historical identities stay saved and resume when that identity returns. Future/anomalous/ambiguous evidence cannot certify publication. MQTT PUBACK means broker acceptance, not CoreScope ingestion. Timeouts invalidate only the affected broker client and recover through its existing credentials/will seam, preventing abandoned MQTT retries accumulating behind the durable queue. Late callbacks cannot resolve a newer claim. Shutdown stops admission, drains bounded jobs and commits resolutions before MQTT/store close; failed local resolution blocks a clean shutdown and pauses that broker's worker.
5. **Activation/evidence:** operator must verify ACL permission for the reporting client's lowercase topic, CoreScope `clientRegions.enabled`, and subscription coverage. Existing observer permissions do not imply client permission. Tests use synthetic persisted answers/transports and contract fixtures; live named-device/CoreScope validation remains #37's separately authorized release gate. No service/broker is enabled by this work.

### 6. Risks and Edge Cases

QoS 1/crash between broker acceptance and local commit may duplicate the same observation; downstream idempotency depends on the deployed compatible ingestor. No ingestion receipt exists. Identity changes must never reattribute history. Clock/observation conflicts remain saved without speculative publication. Broker removal/opt-out preserves pending rows. Reusing an ID for a different destination reuses its delivery history: use a new ID when changing logical destinations. Backfill exports latest snapshots only; earlier unstaged history stays locally queryable. Pending retention may grow during prolonged outages, deliberately favoring preservation. A timed-out broker reconnect briefly affects that broker's ordinary packet/status feed; other brokers/capture remain active. No remote ACL or firmware assumptions are certified by fixture tests.

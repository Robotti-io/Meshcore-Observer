# [v2.5.0][P1-12] Persist supported repeater telemetry and range queries

**GitHub issue:** [#33](https://github.com/Robotti-io/Meshcore-Observer/issues/33)

**Parent epic:** [Pillar 1 — #18](https://github.com/Robotti-io/Meshcore-Observer/issues/18)
**Type:** Feature
**Stage:** Issue scoped; implementation plan pending.

## Outcome and scope

- Define and persist only protocol-supported, validated telemetry/status/neighbour fields associated with full repeater identity and observation time.
- Add selected-range/latest internal queries with approved units, unavailable-field handling, freshness, and retention.
- Keep credential values out of history and preserve single-store migration ownership.

## Acceptance criteria

- [ ] Unsupported/missing fields are distinct from zero and are not invented or converted into unsupported battery/health claims.
- [ ] Samples and neighbour/status representations preserve documented protocol meaning, identity, and time.
- [ ] Strict schema rejection occurs before persistence; queries remain parameterized and bounded.
- [ ] Migrations, retention, reopen behavior, and historical/empty ranges preserve existing installations.

## Validation expectations

Realistic supported-version response fixtures, strict rejection, units/ranges, retention/migration, and query-cost checks; npm test and npm run lint.

## Outcome and scope

- Add opt-in discovery for recently verified zero-hop repeater adverts with full public keys and approved contact prerequisites.
- Use a supported anonymous-request API, direct outbound route and zero-hop reply; correlate matching tags and inspect unexpected flooded send acknowledgements.
- Schedule bounded refresh/retries/backoff, validate normalized answers, and persist successful observations without disturbing normal capture.

## Agreed eligibility policy — 2026-10-08

Under #23/#26, use a runtime-configurable window from the Observer's reception time, refreshed only by verified repeater adverts received with zero recorded hops. General/relayed last-heard observations do not refresh eligibility. Stop scheduling queries after expiry until qualifying evidence returns; preserve inventory and previous successful answers. Operator advert guidance is one-hour zero-hop and 47-hour flood intervals, but actual cadence varies. The approved default is **72 hours**, with a validated operator override and matching example/config-code fallback when omitted. Exact units/window bounds remain implementation-plan details; no automatic per-target cadence assumption is approved. This requirement clarification does not start or complete poller implementation.

### 2. Relevant Existing Architecture

General last-heard, relayed topology, a name or legacy inventory cannot qualify. Existing `PACKETCAPTURE_DIRECT_HEARD_WINDOW_HOURS=72` already has whole-hour 1–8760 validation and matching example/default; reuse it, without adding a second region-specific advert window.
- `src/radio/remote-request-coordinator.js` owns one remote request through terminal completion, separately from `RadioManager.runCommand()`'s short command transaction. It currently rejects `anonymous-regions` with `anonymous-adapter-unavailable`. Its raw `rx` parser validates bounded Sent/Err/BinaryResponse frames, matches a Companion-supplied tag, retains exact listeners, rejects recently retired tags and guards generation changes. ACK/write uncertainty retires the captured connection before releasing ambiguous command ownership. Shared defaults remain ACK 5000ms, response cap 30000ms, spacing 60000ms and one physical attempt/minute, with existing approved override bounds.
- `src/radio/remote-request.js` validates descriptors and prepares binary command-50 operations. The anonymous descriptor is already strictly defined with empty params. Extend only that operation; preserve status/telemetry/neighbour behavior. Do not use legacy high-level helpers that introduce separate timeout/correlation ownership.
- Installed `@liamcottle/meshcore.js` is 1.15.0. Both serial/TCP subclasses implement `sendToRadioFrame`; the installed library has no anonymous or exact-key contact helper. [PR #44](https://github.com/meshcore-dev/meshcore.js/pull/44) is still OPEN/unmerged at `4031dd0a6843cc8dc4d25da1ecf812e1819704b9`, checked during this planning phase through GitHub. An application-owned adapter removes the pending merge as an implementation prerequisite; no installed package edits or version shift are proposed.
- Pinned [Companion command handling](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/examples/companion_radio/MyMesh.cpp) supports exact-key contact read command 30 (`0x1E`) returning Contact/Err, and anonymous command 57 (`0x39`). Command 57 creates a contact if absent and otherwise follows the existing saved route. Contact responses expose a full key and outbound path length. The pinned 64-byte-path Contact layout is 148 bytes, within the existing 176-byte host frame cap. Reject unfamiliar layouts safely instead of interpreting them as zero-hop routes.
- Pinned [repeater handler](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/examples/simple_repeater/MyMesh.cpp) accepts anonymous region type `0x01` only on direct requests. Supplying reply-path length zero requests a zero-hop direct response. Its limiter allows four anonymous queries per 180 seconds shared with other clients/types. Sent result zero also covers routed direct traffic; BinaryResponse contains no target or reply-path proof. Attribute only through captured full-key context and matching tag, with `companion-tag-attributed` provenance; never claim independently measured zero-hop reply delivery.
- `src/metrics/region-history.js` / `region-reads.js` provide atomic result history/latest and per-broker bookkeeping on the owned store. `getRegionLatest` exposes truthful freshness and latest terminal outcome, but its retained coverage counts are unsuitable for a per-row 200-target scheduler scan. Add a focused indexed candidate/scheduling seam, not repeated full coverage queries. Existing migration 14 never records deferred/in-flight RF attempts.
- `src/index.js` constructs the idle shared coordinator; shutdown stops it before outbound schedulers/radio and before owned storage closes. Extend that ordering so the producer first stops scheduling, the coordinator cancels/drains, and terminal result persistence completes while the store/run remains active. The dashboard flag and MQTT connectivity do not control local persistence.

### 3. Proposed Approach

#### Strict configuration and activation

Extend central `config.regions` using centralized strict raw/normalized AJV schemas. No feature module reads `process.env`. Validate explicit blanks, fractions, units, bounds, boolean spelling and cross-field relationships before opening the database or touching hardware/network. Omitted values use matching code/`.env.example` defaults. Existing answer freshness and direct-advert windows remain independent of polling cadence.

| Environment variable | Proposed default | Accepted override / purpose |
| --- | --- | --- |
| `PACKETCAPTURE_REGION_DISCOVERY_ENABLED` | false | Existing strict boolean convention; false creates no discovery timer, contact read, remote request or scheduling write |
| `PACKETCAPTURE_REGION_QUERY_REFRESH_HOURS` | 24 | Whole 1–8760 hours; per-target next normal cycle after success or exhausted retries |
| `PACKETCAPTURE_REGION_QUERY_RETRY_BASE_MINUTES` | 15 | Whole 3–1440 minutes; first failed-attempt delay and known missing/unsafe-contact recheck delay |
| `PACKETCAPTURE_REGION_QUERY_RETRY_MAX_HOURS` | 6 | Whole 1–168 hours; maximum exponential failed-attempt delay; must be at least retry base |
| `PACKETCAPTURE_REGION_QUERY_MAX_ATTEMPTS` | 3 | Whole 1–10 reservations per target/cycle, including the initial attempt; no unbounded immediate retries |
| `PACKETCAPTURE_REGION_QUERY_TICK_INTERVAL_MS` | 10000 | Whole 1000–60000ms; one nonoverlapping bounded selection pass, not an RF interval |
| `PACKETCAPTURE_REGION_QUERY_STARTUP_DELAY_MS` | 60000 | Whole 10000–3600000ms; applies at producer startup, never resets global budgets on reconnect |
| `PACKETCAPTURE_REGION_QUERY_PREFLIGHT_TIMEOUT_MS` | 5000 | Whole 1000–30000ms; exact-key local contact transaction deadline, separate from RF reply timeout |

No redundant per-feature physical-send budget is added. The shared #29 budget remains authoritative, and foreground work/quiet-air checks can defer a due request indefinitely. Retained latest answers can remain stale if there are too many targets for the approved RF budget; expose that truth rather than compressing cadence or dropping targets silently. Opt-in does not prove deployed firmware support; document known source/release evidence, require operator deployment checks before real activation, and handle unsupported responses nonfatally. Never parse the presentation `firmwareVersion` string into a guessed capability gate.

#### Adapter, contact preflight and shared ownership

Add a small pure `region-radio-adapter.js` over the installed `sendToRadioFrame`: contact read bytes `[0x1E, ...32-byte target]`, region send bytes `[0x39, ...32-byte target, 0x01, 0x00]`. Strict AJV validates descriptors/byte arrays and contact envelopes before interpretation or writes. Scope the adapter to these two fixed commands, never a generic externally supplied opcode. Keep serial/TCP framing in the existing library. Recheck the pinned layouts during T1; no uniqueness suffix or caller-chosen tag is appended to anonymous requests.

Integrate preflight into the anonymous branch of the existing coordinator while it owns the remote lease and the same generation-bound command transaction. Do not enqueue a nested `runCommand` or release the local command queue between reading a contact and issuing the request. Attach exact `on`/`off` raw listeners before the local read. Accept only a strict matching full-key Contact with outbound path byte **exactly zero**; unknown `0xFF`, encoded/nonzero routes, missing contacts, malformed layouts, unsupported reads or a generation change authorize no RF. Ignore unrelated contacts without retaining a table/map. Never call command 57 for a known missing contact; it would create one.

After preflight, recheck eligibility, due reservation, connection/Observer identity, foreground priority and quiet-air state immediately before RF. No remote reservation/budget is consumed for ordinary busy/quiet/queue/missing-contact deferrals. If the preflight response/Err is uncertain after a read was written, use bounded targeted connection retirement before another local command can inherit its late reply; provide a fixed message explaining that a contact-read timeout caused the reset. A known Contact or Err is authoritative even if the transport write promise settles late. Add strict phase-specific recovery reasons only as necessary, preserving the logger contract and existing cancellation/close-failure behavior.

Local reads do not consume RF airtime, but run only for an eligible due target after background admission, at most one per tick, with the bounded preflight deadline. Hold no airtime reservation during a slow contact read; acquire/recheck the existing reservation only for the actual region send through ACK/termination. An unexpectedly flooded Sent is `route-mismatch`, consumes the actual global attempt budget and cannot be undone. Await no answer from that request and do not retry via flood. A saved route can change through firmware or another client between preflight and send; this is a residual risk, not atomic routing proof. If runtime hardware evidence shows this window unacceptable, stop and review a firmware/route solution rather than silently mutating contacts.

Preserve #29's one owner, tag/generation/phase checks, retired-tag bounds, ACK/response deadlines and disconnect cleanup. Capture trusted original wall timestamps at actual dispatch and matching binary receipt, before asynchronous producer continuation; use monotonic clocks for deadlines. Returned internal completion context includes those bounded timestamps; immutable reporter/target/run/request identity comes from the admitted request, not wire body fields. Binary payload parsing remains #30's pure strict parser. The host cannot independently verify the response path; request zero hops and retain honest attribution.

#### Restart-safe scheduling on the core store

Propose **migration 15**, confirmed at implementation, adding `region_poll_state` keyed by `(observer_public_key,target_public_key)` on the same owned SQLite connection. Store next-check/due time, cycle start, cycle reservations (bounded by current policy), last policy observation time, nullable last reservation UUID/time/run and fixed last scheduling reason. Use FK protection for a referenced reservation source run, strict CHECK constraints, and due/scope indexes plus a fixed `(type,public_key_hex)` inventory index. No credentials, contact names/paths, raw frames, request tags, broker IDs or public API fields enter this table. Start empty; infer no successful answer or RF attempt from legacy state.

These rows are scheduling metadata, **not durable in-flight RF transactions**. A pre-send reservation is not evidence a request reached the radio or repeater. At the final send boundary, a synchronous trusted callback atomically reserves a new request UUID/current run, consumes one target-cycle reservation and saves a conservative next deadline **before** the global budget/transport dispatch. If that write fails, send no RF. A crash after reservation but before transmission can therefore consume a slot conservatively; never replay its wire request on restart and never manufacture a terminal outcome. Global physical-send accounting still uses #29's actual dispatch boundary. If priority/budget/generation changes after reservation, keep its conservative cooldown instead of undoing durable evidence optimistically.

Add narrow strict store methods for keyset candidate pages, scheduling deferral, conditional reservation and conditional completion. Pages default/max **100/200**, ordered by full target key with a bounded cursor, scoped to the current validated Observer key. Join latest receipt/flags and poll state directly without retained-history counts or per-row body parsing; filter current verified-direct eligibility and due state, then recheck the selected target through the existing eligibility seam. Scan at most one page per tick and select at most one target, advancing fairly and wrapping after exhaustion. No unbounded target/contact maps or fixed lifetime target cap. A new reporter uses its own schedule; never transfer another Companion's success/backoff state.

Seed an uninitialized target from existing reporter-scoped latest success/outcome where appropriate: a recent measured empty/nonempty success need not be immediately re-queried. Due time uses the configured refresh interval from original receipt; policy changes recompute that baseline within bounded reads. Existing terminal failure evidence imposes at least the base cooldown. No history reconstruction or fabricated attempt count is claimed; migration has no historical retry budgets to recover. Persist initialized policy state so later retries/restarts use saved deadlines, not increasingly old ledger scans.

On completion, validate the full strict result and matching reservation/request/current run, then atomically commit #30's terminal outcome/optional measured answer with the next schedule. Refactor only a private transaction seam if needed to avoid nested SQLite transactions; preserve `recordRegionResult`'s existing public-internal contract, idempotency, ambiguity and rollback tests. Success, including `[]`, resets the retry cycle and schedules refresh from original receipt. A supported command-level `unsupported` Err is recorded separately and pauses the target for one refresh interval; silence stays `response-timeout`, never unsupported. Other terminal failures increment bounded retry policy: exponential base × 2^(reservations−1), capped by configured maximum, with only positive 0–10% jitter capped at the maximum. Exhausted cycles wait one refresh interval before a new cycle; new adverts/reconnects do not erase deadlines or replenish reservations.

Known preflight missing/unsafe routes are typed scheduling deferrals with base-delay recheck and fixed transition warnings, not terminal region outcomes or physical-send counts. Preflight unsupported/uncertain read pauses this producer for the captured generation and preserves scheduling state; a new ready generation allows bounded reconsideration. Ordinary busy/quiet/rate/not-ready deferrals add no outcome rows and no per-poll logs/writes. A persistence failure after a valid response preserves prior latest and the pre-saved cooldown, emits a fixed safe warning and starts no immediate re-query. No crash-before-terminal evidence is fabricated as an empty list.

Use wall time only for saved observations/deadlines, with a process high water seeded from durable run and scheduling evidence and monotonic elapsed progression. During rollback, pause RF until clock agreement; never make expired eligibility fresh or a retry due because time moved backwards. Future/clock-anomalous/ambiguous latest data does not prove a fresh answer; retain it and resolve through a later eligible observation without manufacturing time. Apply #26's existing 72-hour direct window at admission and dispatch, expiry at equality. Clock-anomaly flags accompany any terminal result whose captured wall times disagree; original times remain unchanged.

Scheduling state survives shared history pruning, disabled discovery, absent brokers and restart. It is not a substitute for retained answer/outcome coverage. Preserve rows and needed source-run FKs by default; no automatic abandonment or target-catalog purge is introduced. Changing cadence/attempt limits applies conservatively: lowered limits can stop a cycle, while raising limits or shortening cadence must not accelerate an already saved active retry/cooldown. New normal cycles use current settings. Document long outages/forward clocks and indefinite per-pair state as capacity/availability limits.

#### Producer and shutdown integration

Add a small injected `RegionDiscoveryScheduler` with one unreferenced timer, one in-progress operation and a bounded candidate page/cursor. Receive config, store/current run, radio/coordinator, logger, wall/monotonic clocks and jitter function. Construct/start only when enabled; local stored answers remain available either way. The scheduler never depends on MQTT or metrics-server readiness. It pauses selection on disconnected/not-ready state and validates the current full Observer key; reconnect invalidates preflight/tag state through #29 but preserves process/global/durable target budgets. No catch-up burst or timer accumulation.

At shutdown stop the timer/admission first, cancel/drain the coordinator, await the producer's conditional terminal persistence, then continue existing outbound/radio teardown and owned-run completion. Dispose exact listeners and clear only transient candidates/tags. A failed final persistence or shutdown deadline cannot claim a successfully saved observation or clean teardown; follow existing shutdown truthfulness. Any coordinator reset is explained through fixed structured warnings; no raw error text, body, contact table or credentials are logged.

#31 always calls the result seam with `brokerIds:[]` and starts no publication worker. #32 will separately decide staging/backfill and broker policy. Opt-in queries can therefore produce useful offline region history immediately once implemented, without approving MQTT destinations here.

### 6. Risks and Edge Cases

- Command 57 can create a missing contact in firmware. A read-only preflight narrows this risk but cannot lock out another client deleting/changing contacts between commands. Do not promise firmware-side atomic route/contact policy or restore state that this feature never intentionally edits.
- Direct Sent proves route class, not hop count; BinaryResponse has no target/path proof. Full-key/tag attribution and requested zero-hop reply are the available host evidence, and firmware/deployment validation remains necessary.
- Read preflight adds bounded local queue occupancy. Missing/malformed/late responses can require a connection reset, temporarily interrupting capture; the fixed warning must explain why. Read deadlines never hold the RF airtime reservation.
- The shared RF budget may take hours to cover a large fleet. Refresh is a minimum per-target interval, not a freshness SLA; foreground work can defer it indefinitely. One page/tick and fair keyset rotation bound memory without silently discarding targets.
- Scheduling reservations are conservative, not sent counts. Crash/persistence/priority races can use a cycle slot without RF; this trades availability for preventing restart bursts. No RF request is replayed from a saved reservation.
- New migration/transaction changes must preserve four-table region/outbox semantics and existing legacy datasets. Back up the closed owned database before upgrade; rollback uses a compatible backup rather than manual schema deletion. Scheduling rows/FKs survive shared history pruning and grow with reporter/target pairs.
- Clock rollback pauses traffic; forward jumps or longer saved cooldowns can delay queries after corrections. Original observations remain saved and clock uncertainty is explicit. Changed settings do not erase active saved backoff.
- An unsupported Companion command is observable; repeater silence cannot distinguish firmware, busy limiter, path or RF loss. Avoid unsupported claims or password fallback based on timeout. Actual firmware minima are not inferred from library merge or build-date text.
- #30's ambiguity and unknown completeness remain authoritative. #31 must not turn a short/empty response into complete configuration or create a new timestamp to evade a collision.

# [v2.5.0][P1-13] Poll repeater telemetry within a configured hop radius

**GitHub issue:** [#34](https://github.com/Robotti-io/Meshcore-Observer/issues/34)

**Parent epic:** [Pillar 1 — #18](https://github.com/Robotti-io/Meshcore-Observer/issues/18)
**Type:** Feature
**Stage:** Issue scoped; implementation plan pending.

## Outcome and scope

- Select eligible repeaters using fresh passive evidence and validated outbound contact/routing behavior; enforce configured hop radius.
- Use approved telemetry-only authentication with protected default/override credential references, separate from management and anonymous regions.
- Distribute requests across a configurable cadence with bounded timeouts/backoff/retries, validate responses, and persist supported observations.

## Acceptance criteria

- [ ] Radius and freshness limit requests; stale/ambiguous evidence cannot trigger blind probing or management login.
- [ ] Successful/failing routes are handled according to verified protocol rules without assuming inbound path reversal.
- [ ] Telemetry credentials do not enter metrics, APIs, logs, or error details.
- [ ] Busy air, radio disconnects, unreachable nodes, and auth/protocol failures cannot create bursts or starve normal capture/bot work.
- [ ] Invalid configuration fails before hardware/network effects; operation is opt-in as approved.

## Validation expectations

Radius, route/auth, scheduling/backoff, schema, secrets, mixed-workload, disconnect/restart tests; npm test and npm run lint and separately authorized hardware checks.

telemetry service; shared radio coordination; central configuration/secret references; store integration.

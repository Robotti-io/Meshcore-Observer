#### Protocol evidence and limits

Primary firmware baseline is [MeshCore a366955](https://github.com/meshcore-dev/MeshCore/tree/a366955cb2f67b8e6842d4f00d2b6a554dddd88a); the installed library is `@liamcottle/meshcore.js` 1.15.0 ([tag source](https://github.com/liamcottle/meshcore.js/tree/1c142946f9597d60fc634afd9a681f546792b0d5)). These are source/fixture evidence, not attestation of deployed hardware.

- [Repeater login and query handlers](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/examples/simple_repeater/MyMesh.cpp): an empty password can reuse existing ACL membership; management-password comparison precedes guest-password comparison. Even guest login establishes transient remote ACL/session state. Permit blank guest fallback, but accept only modern proof of guest-only permissions before sending telemetry data; never try management credentials.
- [Client ACL roles](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/src/helpers/ClientACL.h): role bits 0/1/2/3 mean guest/read-only/read-write/admin. Require a modern response proving role 0 and `isAdmin=0`; reject every other role, legacy success and missing permission fields.
- [Companion response and command handling](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/examples/companion_radio/MyMesh.cpp): modern host LoginSuccess is exactly 14 bytes (0x85, admin flag, six-byte key prefix, server timestamp, permissions, firmware level). LoginFail is eight bytes. The Sent tag is the target's first four key bytes, not a request nonce. Companion pending login also uses four bytes. The installed library omits modern permission fields, so use the coordinator's exact raw-frame listener and centralized schemas rather than its unbounded login helper.
- [BaseChatMesh login](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/src/helpers/BaseChatMesh.cpp): repeater passwords truncate at 15 UTF-8 bytes; permit empty guest passwords, but reject oversize, NUL/control or invalid encoding rather than silently trimming/truncating. Unknown contact path triggers flooding; never admit it.
- [Path encoding](https://github.com/meshcore-dev/MeshCore/blob/a366955cb2f67b8e6842d4f00d2b6a554dddd88a/src/Packet.h): decode hash width and relay count, validate firmware-supported width and contact capacity, and enforce `relayCount + 1 <= radius`. Do not compare the encoded byte directly to radius. Direct reception/contact is distance one.
- Guest sensor requests are forced to the base sensor mask in this firmware: battery and supported MCU temperature may be available; environmental temperature/humidity/pressure/current are not promised. Firmware level in login is not telemetry layout/emitter attestation. Preserve #33 unknown/partial semantics.

### 3. Proposed Approach

The user approved the following concrete decisions together on 2026-10-10. Earlier best-judgment direction resolves routine defaults; the explicit finalized-plan approval covers the protected authentication and durable scheduling model.

**POLL-PLAN-01 — Opt-in configuration and protected secrets.** Keep polling disabled by default. Resolve policy and an optional protected secret-reference file only through central startup configuration, with strict AJV and bounded file reads. An intentionally configured shared community credential uses the default reference; when that default has no secret entry, use the blank guest password. Full-key target overrides take precedence over one explicit group override, then default. Reject overlapping group assignments, duplicate targets and missing non-default references. Never select credentials by display name or shortened prefix, infer a nonblank built-in password, cycle credentials after failure or reuse management/broker secrets. No live reload. Missing optional configuration uses matching code/example defaults; invalid explicitly supplied configuration fails even when disabled.

| Setting | Proposed default / bounds |
| --- | --- |
| Polling enabled | false |
| Maximum hop radius | 2; integer 1–63 |
| Passive eligibility window | 72 hours; integer 1–8,760 |
| Component refresh cadence | 24 hours; integer 1–8,760 |
| Startup delay / scheduler tick | 75 seconds / 10 seconds; 1–3,600 / 1–60 |
| Contact preflight timeout | 5 seconds; 1–30 |
| Successful guest-session reuse | 10 minutes; 1–60; generation/reporter scoped |
| Retry base / maximum | 15 minutes / 360 minutes; positive with base <= maximum |
| Maximum physical attempts per component cycle | 3; integer 1–10 |
| Authentication denial/unsafe-response cooldown | 24 hours; integer 1–8,760 |
| Sensor permission mask | 0; guest base sensors only |
| Neighbours request | version 0, count 3, offset 0, order 0, prefix 32; one page |
| Shared ACK / response ceiling / physical budget | Existing 5s / 30s / one per minute defaults, unchanged |
| Historical retention | Existing shared 0/indefinite or configured days |

Use `PACKETCAPTURE_TELEMETRY_POLL_ENABLED`, `..._POLL_RADIUS`, `..._POLL_EVIDENCE_HOURS`, `..._POLL_INTERVAL_HOURS`, `..._POLL_STARTUP_DELAY_SECONDS`, `..._POLL_TICK_SECONDS`, `..._POLL_PREFLIGHT_SECONDS`, `..._POLL_SESSION_MINUTES`, `..._POLL_RETRY_BASE_MINUTES`, `..._POLL_RETRY_MAX_MINUTES`, `..._POLL_MAX_ATTEMPTS`, `..._POLL_AUTH_COOLDOWN_HOURS`, `..._POLL_CONFIG_FILE`, and `..._POLL_SECRETS_FILE` in the existing central config. Default file paths are absent: enabled polling requires an explicitly supplied policy; its secret file is optional and a missing default password means blank. Disabled omission performs no reads or RF work. Validate explicit paths/files before side effects, including when disabled.

Policy JSON version 1 contains a default credential reference, explicit full-key targets/groups, component parameters and verified profile overrides. Bound it to 256 distinct target assignments, 16 groups and 64KiB. Secret JSON version 1 contains at most 32 bounded reference IDs and guest-password strings, also <=64KiB. Passwords may be empty; nonempty values must encode to at most 15 bytes and contain no control characters/unpaired surrogates. `.gitignore` excludes local `telemetry.config.json` and `telemetry.secrets.json`; example files use clearly synthetic credentials and document read-only container mounts/operator filesystem permissions. Do not inspect real operator files. Do not include raw JSON/parser errors, paths, values, references or fingerprints in logs, metrics, APIs or startup error details. Private credential material stays in a narrowly scoped resolver, never public request descriptors or store records.

**POLL-PLAN-02 — Passive evidence plus independently validated outbound routes.** Candidate eligibility is either verified zero-hop evidence recorded for the current reporter, or fresh reporter-scoped flood topology with unique full-key repeater resolution within radius. Both exclude the Observer, room servers, stale/future/anomalous evidence and ambiguous prefixes. Merge/dedupe by full key, using bounded indexed keyset pages and an exact per-target eligibility read before each RF operation. Do not hydrate all historical topology to recheck one request. Persist new reporter-scoped direct markers only from newly verified adverts with captured original `origin_id` and receipt time; do not backfill from the unscoped inventory or infer current identity at asynchronous completion.

Read the full contact inventory through the shared local command owner before a login, bounded to 1,024 contacts and the preflight deadline. Require exactly one target and no first-four/first-six-byte prefix collision; reject an all-zero first-four-byte prefix. Before every physical login or data request, re-read the exact full-key contact, require repeater type and a valid saved direct path, and recheck current reporter/generation/evidence. Decode and bound route bytes and relay count. Unknown/flood routes, malformed contacts, collisions and mismatched actual ACK route fail closed. Never reverse inbound paths, add/edit/evict contacts, request paths, issue CLI commands or use flood fallback. Contact inventory size/timeout limitations are explicit defer reasons.

**POLL-PLAN-03 — Guest-only login through the existing owner.** Add a narrow internal guest-login flow to the same remote coordinator, with transient private password preparation and sanitized public outcomes. Complete schema validation, contact/prefix checks, budget checks and synchronous durable reservation before physical send. Match the ACK's static target prefix and exact raw modern login frame within one generation-scoped pending owner. Validate modern role 0, admin flag 0, supported protocol shape and public server-time replay guards before authorizing data. Persist safe authentication outcome before using a bounded in-memory session; clear sessions on disconnect, generation/identity change, expiry or failure. Never restore authority from database history after restart.

Reject duplicate/retired responses through bounded prefix quarantine and persist the greatest accepted server timestamp as a conservative known-replay guard. Timestamp rollback/reset pauses authentication until later fresh proof/operator repair; it is a server clock, not an echoed nonce. This protocol cannot independently prove full-key or nonce binding for same-target delayed login replies. Full contact uniqueness, raw frame validation, one owner, generation guards and cooldown reduce that risk but do not remove it. If deployed protocol support does not meet these gates, defer rather than broaden permissions or change dependencies.

An operator could accidentally supply a nonblank guest password also configured as the management password; firmware may already grant admin during login before the host rejects the reply. The host cannot pre-prove password separation or undo remote login. Guidance must keep any configured nonblank guest password distinct from management; the blank default still requires validated guest-only proof before telemetry data is sent. Unsafe role responses stop further queries with a safe fixed reason. Guest login can change transient remote ACL/session state.

**POLL-PLAN-04 — Durable save-first scheduling and outcomes.** Add one owned-store migration, expected version 17 after rechecking the head, with three narrowly scoped datasets:

1. `telemetry_direct_evidence`: reporter/target key, verified zero-hop original receipt, source run and compact provenance/digest. Latest marker remains after historical pruning; stale evidence never grants eligibility.
2. `telemetry_auth_outcomes`: immutable attempt identity, reporter/target/source run, captured local dispatch/completion times, actual route, bounded outcome/fixed reason and validated public permission/firmware/server-time fields. No raw login frame or credential data/reference/hash.
3. `telemetry_poll_state`: reporter/target/component/canonical parameter scope, cycle/attempt/due times, reservation identity/source run, conservative policy timing, fixed reason and public authentication replay high-water. Retain minimum state across restart/pruning without creating a durable RF replay queue.

Use existing owned connection, run FKs, prepared/indexed bounded keyset/exact reads and strict DTOs. Reserve synchronously immediately before each physical login/data send. Deferrals and local contact reads do not consume RF attempts; failed physical sends do. Write data outcome/observation through #33 and advance the matching reservation atomically by adding a narrow internal within-transaction recorder, preserving its public contract. Authentication failures belong only in authentication outcomes if no binary query was dispatched. Never invent status/sensor/neighbour results. Terminal write failure pauses new telemetry work and retains at most one bounded unsaved terminal for drain; close store only after producer/coordinator drain. Unresolved reservation recovery advances cooldown conservatively without synthesizing responses or immediate replay.

Apply shared original-time days retention to auth history; protect latest public replay state, direct markers, active/latest poll state and required source runs. Use the existing shared pruning mechanism, not another timer/store. Nonsecret permission history is evidence, never a reusable live grant. All defaults are save-first; indefinite retention has no lifetime disk ceiling. Schema migration/ownership/write failures stop or pause safely even with dashboard/MQTT disabled.

**POLL-PLAN-05 — Bounded distributed work and fairness.** Add an opt-in telemetry scheduler using monotonic elapsed time plus durable wall-clock high-water. At most one pending request, one bounded unsaved terminal, bounded candidate cursor and a 32-entry ephemeral guest-session cache. Spread first-cycle due times deterministically over cadence; process components incrementally rather than issuing three-request bursts. Preserve foreground replies/adverts and capture. Add bounded background-demand arbitration to the existing coordinator for anonymous-region and telemetry producers: one expiring demand per source and alternate physical admissions when both remain eligible. Startup staggering alone does not establish fairness. No unbounded queue and no background guarantee under sustained foreground/busy air.

Require fresh eligibility and contact proof again after waiting. Login consumes the same physical budget as data. Timeout/unreachable/protocol failures use capped exponential backoff and attempt limits; exhausted cycles wait for the regular refresh. Authentication rejection/unsafe role uses the longer cooldown, no alternate credential. Changes toward slower settings may only extend durable due times conservatively. Wrong route/uncertain ACK/preflight ownership follows existing targeted generation recovery; reconnect/restart never resets physical rate state into an immediate burst. Report fixed safe reasons for deferred/unsupported/unavailable outcomes through existing structured logging, without altering its contract. Measurement age, evidence age, contact validity, poll attempts, successful replies and sensor availability are distinct.

**POLL-PLAN-06 — Conservative telemetry contracts and rollout.** Reuse #33 status/sensors/neighbours schemas and profile allowlists. Default unknown status layout only uses the established common prefix; unknown sensor emitter remains undecoded. Operator verified overrides are explicit, target scoped and cannot be inferred from names/login firmware level. Guest base mask 0 is fixed for this phase. Default neighbour count 3/full-key prefixes reflects pinned bounded payload capacity; no automatic pagination or completeness claim. Empty, partial, unsupported and latest failure never overwrite a retained useful observation as if it were complete/current. Keep original reporter, run, target, tag, route, parameters and captured dispatch/receipt times. Preserve exact tagged data correlation separately from weak login correlation.

### 6. Risks and Edge Cases

- Login prefix/static-tag correlation is weaker than tagged telemetry and cannot provide nonce-based replay proof. Full contact uniqueness and public server-time guards fail closed; contact mutation outside the owner and same-target delayed replies remain residual limitations.
- A wrong nonblank credential that equals management can cause remote admin ACL establishment before host rejection. Blank is the MeshCore guest default when no password is configured; the application accepts only validated guest-only permission proof before sending telemetry data and never deliberately requests or uses management permission. Guest login can still change transient remote ACL/session state.
- Guest-only sensor access may leave environmental fields unavailable. Unsupported source profiles/legacy firmware remain explicit unknown/deferred states, rather than relaxing authentication or decoding assumptions.
- Existing radio contact routes may be absent despite excellent passive evidence. This phase skips such repeaters; it does not create routes or repair contact tables. A large table beyond the conservative bound pauses login preflight.
- Two-hop/default-24h coverage is a configurable objective, not a guarantee. Login plus three data requests competes with region polling under one shared physical request/minute; busy air/foreground work and many nodes extend cycle time. Disclose effective coverage and lower bounds.
- Public server clocks can reset; durable high-water then defers login until fresh proof or deliberate repair. Local clock reversal, future evidence and orphan reservation likewise defer, never make stale state fresh.
- Always-on reporter-scoped passive markers add storage writes even when polling is disabled, but no radio work. Preserve existing advert transaction/dedupe/count semantics and startup migration guarantees.
- Retention may remove historical interactions while retaining required replay/latest markers and run references. These retained markers do not establish a live guest session. Indefinite retention remains operator-managed capacity.

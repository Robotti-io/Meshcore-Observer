### 1. Feature Summary

Persist verified advert events separately from current full-key inventory, include unnamed Companion/Repeater nodes, and retain independent verified zero-hop repeater reception timestamps for region-query eligibility. The approved default eligibility window is 72 hours with an operator override.

### 2. Relevant Architecture Before Implementation

- `src/nodes/advert-parser.js`: parses an installed-library `Advert`, leaving signature verification to the caller.
- `src/nodes/node-registry.js`: currently rejects unnamed adverts before `isVerified`; verified named adverts call `upsertNode` using a clock read after asynchronous verification.
- `src/packets/packet-normalizer.js` and `packet-decoder.js`: reception time is captured before decode and becomes `packet.timestamp`. The public MQTT shape has no hop/path evidence fields; local consumers can parse `packet.raw` without changing that public shape.
- `src/packets/packet-pipeline.js`: emits all decoded receptions, including alternate paths. Preserve that behavior.
- `src/packets/packet-hash.js`: protocol-compatible hash is a truncated SHA-256 value; ADVERT hashing excludes path. Do not use a short compatibility hash alone as the new durable event uniqueness constraint.
- `src/metrics/store.js`: `nodes` was current inventory with `name NOT NULL`, immutable first-heard and mutable last-heard. Existing history reads could not reconstruct advert events. #28's committed migration 9 is the baseline; this feature adds migration 10. Shared `pruneOlderThan` preserves nodes.
- `src/bots/command-handlers/lookup.js`: uses raw nullable name data. Its display boundary needs an `Unnamed` fallback when required; inventory must not store an invented received name.

### 3. Proposed Approach

Build a strict internal verified-advert DTO after successful signature verification, containing full public key, nullable received name/type, Observer reception epoch-ms, full digest of the signed advert payload, and decoded recorded-hop count. Validate centralized schemas before persistence. Reparse local frame metadata using the installed library; retain existing MQTT output unchanged.

Propose a transactional store method that deduplicates an advert event, preserves/updates inventory, and updates qualifying reception evidence independently. `advert_events` stores event digest, node key, first Observer reception time, received name/type snapshot, and whether this event first discovered the inventory key. A same-advert relayed/direct reception contributes one event but can still refresh direct evidence. Store only useful structured evidence; never store the raw frame locally.

Use nullable actual names, with `Unnamed` at presentation boundaries. Preserve the latest known non-null inventory name when a later unnamed advert arrives; store the unnamed event's actual name as null. Protect first/last-heard and latest-name selection against verification finishing out of reception order. Retain current registry support for other types while limiting the new reporting scope to Companion/Repeater.

Propose a small durable direct-heard state keyed by full public key with `last_direct_heard_at`; it survives advert-history pruning and restart. Region eligibility requires repeater type plus verified zero recorded hops and a non-expired reception timestamp. No query is scheduled by this issue. #31 rechecks eligibility immediately before dispatch.

Approved central `PACKETCAPTURE_DIRECT_HEARD_WINDOW_HOURS=72` is parsed in `src/config/index.js`, normalized to integer milliseconds and validated in `src/config/schema.js`. Override bounds: positive whole hours up to 8760, with no zero/unlimited sentinel. Example and code defaults match. Expire at `now >= lastDirectHeardAt + windowMs`; future-dated evidence is ineligible until the clock catches up, without resetting saved evidence on restart.

Event history uses shared metrics retention; inventory and current direct timestamp survive that cleanup. The user approved indefinite fingerprints by default on 2026-10-08, preventing identical replay from recreating history while its fingerprint survives. Migration 10 uses a 32-byte digest ledger associated with inventory by compact internal ID; it contains no raw frame or message body. Under the user's delegated judgment, optional cleanup removes only expired-event/non-discovery fingerprints for inactive repeaters; inventory and original discovery remain durable. Unlimited growth is an explicitly accepted default, with measured costs recorded in execution evidence. Detailed behavior and limits are recorded in section 9 and README.

### 6. Risks and Edge Cases

- Verification is asynchronous while SQLite writes are synchronous: preserve reception chronology and atomic new-node classification.
- Current nullable-name assumptions differ between storage and display; review compatibility in lookup, existing node routes, and reporting without silently broadening API scope.
- Historical digest retention can grow even after event detail is pruned. This is a concrete storage decision, not an already-approved consequence of shared metrics retention.
- Signature verification establishes authenticity of advert content, not guaranteed current reachability; received zero-hop evidence still has a finite configured lifetime.
- Persisted timestamps survive restart, but clock changes need conservative handling. No process-local timer should grant a fresh 72 hours on restart.

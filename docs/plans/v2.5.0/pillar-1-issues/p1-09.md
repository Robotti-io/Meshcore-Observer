# [v2.5.0][P1-09] OBS-02: Persist region answers and freshness

**GitHub issue:** [#30](https://github.com/Robotti-io/Meshcore-Observer/issues/30)

**Parent epic:** [Pillar 1 — #18](https://github.com/Robotti-io/Meshcore-Observer/issues/18)
**Type:** Feature
**Stage:** Issue scoped; implementation plan pending.

## Outcome and scope

- Persist successful region lists, target identity, observed timestamp, optional repeater clock, and the approved completeness/freshness representation.
- Represent failed/unknown attempts separately if approved; keep transient request tags in bounded memory.
- Provide internal reads needed by scheduling and MQTT publication, including the approved publication retry/restart state.

## Acceptance criteria

- [ ] Successful empty lists persist as measured answers; timeout/malformed/unsupported responses preserve the last successful answer.
- [ ] Region case and * wildcard semantics are preserved; any truncation heuristic never claims proven completeness.
- [ ] Normalized answers are validated through centralized strict AJV schemas before persistence.
- [ ] Store reopen, migrations, freshness/retention, and publication-state recovery preserve existing datasets.

## Validation expectations

Valid/empty/malformed, stale/unknown/partial, name case/wildcard, reopen/migration, and retention fixtures; npm test and npm run lint.

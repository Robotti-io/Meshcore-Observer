## Outcome and scope

- Expose approved bot aggregates, advert/node activity, path evidence, run/resource history, and repeater telemetry through focused viewer queries.
- Reuse existing range semantics and centrally validate all inbound query/route data, with bounded filtering/pagination/bucket costs.
- Define stable response units, freshness, unavailable/empty behavior, and backward-compatible existing endpoints.

## Acceptance criteria

- [ ] Presets/custom ranges agree with store semantics, with current inventory separated from historical events.
- [ ] Invalid queries are rejected before logic; existing API behavior and request/application logging/security contracts are preserved.
- [ ] Secrets/private content and unnecessary sender detail are not exposed.
- [ ] Long-retention responses remain bounded, and dashboard-disabled persistence works independently.
- [ ] OBS-02's initial contract remains MQTT-only; an additional region reporting surface requires separate scope approval.

## Validation expectations

HTTP query/schema/range, existing endpoint compatibility, response semantics/privacy, and bounded query tests; npm test and npm run lint.

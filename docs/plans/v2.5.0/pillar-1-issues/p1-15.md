# [v2.5.0][P1-15] Connect telemetry, node, bot, and runtime dashboard reporting

**GitHub issue:** [#36](https://github.com/Robotti-io/Meshcore-Observer/issues/36)

**Parent epic:** [Pillar 1 — #18](https://github.com/Robotti-io/Meshcore-Observer/issues/18)
**Type:** Feature
**Stage:** Issue scoped; implementation plan pending.

## Outcome and scope

- Connect approved datasets to overview/drill-down views without duplicating every metric on the overview.
- Label units, ranges, freshness, event/unique/inventory and invocation/delivery distinctions; expose practical textual/tabular values.
- Reuse the Pillar 4 shared navigation/control/accessibility foundation and existing stale-request/update-coalescing seams.

## Acceptance criteria

- [ ] Current/historical and empty/stale/unavailable/error states have accurate meanings.
- [ ] Filters/ranges/drill-down retain correct scope across refreshes; partial failures preserve other healthy data.
- [ ] Long identifiers, large result sets, keyboard controls, and narrow layouts are usable; untrusted labels stay escaped.
- [ ] Rendering/SSE refresh remains measured and bounded.
- [ ] Visual system ownership stays with Pillar 4; no new framework, chart library, asset, CSP, or OBS-02 dashboard is silently added.

## Validation expectations

Meaningful dashboard logic/interaction tests plus keyboard/responsive/manual data checks and measured update cost; npm test and npm run lint.

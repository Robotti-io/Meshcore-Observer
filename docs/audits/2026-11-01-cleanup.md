## Policy decisions made within approved batches

- Packet capacity/deadlines are loss-reporting safeguards, not durable retries. A packet beyond capacity or without completion may be lost; it is reported failed, never sent. Actual broker delivery after an uncertain acknowledgement is not asserted. Recovery discards that retired client's queue to bound retained work. Operators needing a different delivery guarantee require a separate design.
- SSE is current-state streaming: intermediate snapshots may coalesce. Reconnect obtains a fresh snapshot. The cap/payload rejection uses HTTP503 and does not disable ordinary metrics endpoints.
- Native HTTP preserves the deliberately unauthenticated, optional viewer and loopback default. Hardening adds no cross-origin access. Request IDs are generated internally; hostname comes from the OS, not untrusted Host headers. Required HTTP/application pairs bypass only the standalone log-level suppression, while request debug logs still respect it.
- Separate telemetry mode now accounts for the trace's actual RF turn. Controlled-clock fixtures must advance through trace, login and each data turn; shortened test expectations are not preserved as product behavior. Reservations keep the original pre-trace time; a refreshed inventory is not a fresh durable auth attempt.

## Operational limits

Live firmware/RF acceptance, deployed broker behavior, clean dependency install, full Linux/Node22 matrix, remote CI/branch protection and production deployment were not performed. Local fixtures establish implemented behavior; they cannot prove radio firmware behavior or remote policy enforcement. The 5-second local command deadline may cause reconnection on an unusually slow companion; uncertain closure remains fail-closed.

Optional architectural/API redesign, mass formatting and speculative abstractions were deliberately left out. The single SQLite owner, shared radio owner, domain schedulers, command-handler seam, native HTTP and no-build browser remain intact.
